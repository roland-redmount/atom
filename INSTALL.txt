*
*  Installation instructions
*

This is the source distribution for the atom system. It can be installed and built on Linux and (maybe) Windows.

Besides the source in this distribution, atom may require installing additional software. We currently don't have an automated installer, so you may have to do some package installation upfront.

*
* Graphics 
*

The following are required for graphics. We could do text interface without.


** SDL2 (Simple Direct Media Layer) **

Linux (Ubuntu, Debian):  sudo apt install libsdl2-2.0-0 libsdl2-dev
Windows: see https://github.com/libsdl-org/SDL/releases


** GLEW (OpenGL Extension Wrangler) **

Linux (Ubuntu): sudo apt install libglew2.2 libglew-dev glew-utils


** FreeType (font rendering) **

Linux (Ubuntu): sudo apt install libfreetype-dev

To get the required include file paths, do: pkg-config --cflags freetype2

*
* WebAssembly
*

The web front end (src/ui/web.c) is built with emscripten, installed with the
emsdk from https://github.com/emscripten-core/emsdk. Put it on the path, then:

  source <emsdk>/emsdk_env.sh
  emcmake cmake -B build/wasm -DCMAKE_BUILD_TYPE=Debug
  cmake --build build/wasm

emcmake names the emscripten toolchain file for cmake, which is how the build
knows it is building for the web; there is nothing else to pass. A Debug build
is what defines DEBUG and so keeps ASSERT() live, and a violated one has to
stop the session rather than be undefined behaviour. Such a build is compiled
for size rather than for debugging, since a page downloads it.

The result is collected in build/wasm/web, which is a directory a web server
can serve as it stands: open index.html to try the snippet element out. To put
the front end in a site that serves it, see web/publish.sh.
